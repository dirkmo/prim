# Executable Forth examples

Each file is ordinary ASCII Forth source for this kernel, not TokenForth.
Start every example with a fresh kernel session:

```sh
python3 forth/run.py < forth/examples/basics.fs
python3 forth/run.py < forth/examples/loops.fs
python3 forth/run.py < forth/examples/data.fs
python3 forth/run.py < forth/examples/strings.fs
python3 forth/run.py < forth/examples/immediate.fs
```

The simulator echoes input and adds `ok` or `compiled` responses. The table
shows only the additional program output; numeric output includes a trailing
space, and each listed output line ends in CRLF.

| File | Program output lines | Features |
| --- | --- | --- |
| basics.fs | `49 `, `9 ` | Native definitions, multiplication, signed conditional |
| loops.fs | `3 2 1 `, `0 `, `99 ` | Multiline definition, WHILE/REPEAT, UNTIL, IF/ELSE |
| data.fs | `15 `, `42 `, `AB` | VARIABLE/+!, CONSTANT, CREATE/C,/TYPE |
| strings.fs | `Hello, Forth!`, `A persistent string`, `temporary`, `Z` | Both string forms, persistent bytes, XT/EXECUTE |
| immediate.fs | `42 `, `1 ` | IMMEDIATE, LITERAL and compile-state observation |

All examples leave an empty user stack and no open definition. The independent
expected responses for every physical input line are stored in expected.json:
`responses` includes the program output and its final prompt; `stack` is the
expected final user stack. Tests prepend the startup `ok`, account for echoed
input, compare the complete transcript and verify the final stack. Expectations
are not generated by running the implementation.

```sh
python3 forth/tests/test_examples.py --rtl -v
```

The integrated runner/CTest also executes these checks: CPU model, the documented
pipe workflow from a foreign working directory, RTL UART-buffer execution, and
word-reference completeness. The complete serial-RX system boundary has a
separate mixed integration test. On hardware, use the credit-controlled host
console described in the main guide; an unpaced source-file paste can overrun
the one-byte RX register.
